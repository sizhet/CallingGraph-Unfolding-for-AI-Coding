# 4. Fig-001 — Folding and Unfolding

**File:**

[`figures/Fig-001-Folding-and-Unfolding.png`](figures/Fig-001-Folding-and-Unfolding.png)

## Core Message

Fig-001 introduces the most fundamental CGU relationship:

$$
Program
\xrightarrow{Folding}
CallingGraph
$$

and:

$$
CallingGraph
\xrightarrow{Unfolding}
LocalizedFunctionalPossibility
$$

The key distinction is:

$$
\boxed{
Unfolding
\neq
Inverse(Folding)
}
$$

## What the Figure Shows

The Folding side suppresses implementation detail while preserving functional topology.

The Unfolding side selectively expands functional possibilities from the folded structure.

The result is not exact source-code reconstruction.

Instead, it is:

$$
\boxed{
Localized\ Structural\ Elaboration
}
$$

$$
DT\text{-}CG

$$
RT\text{-}CG

# 8. Fig-005 — Unfolding Gap

**File:**

[`figures/Fig-005-Unfolding-Gap.png`](figures/Fig-005-Unfolding-Gap.png)

## Core Message

Fig-005 visualizes one of the most important results in CGU:

$$
\boxed{
CallingGraph\ Match
\neq
Unfolding\ Equivalence
}
$$

Two structures may appear similar when folded but reveal different local expansions when activated.

The Unfolding Gap is:

$$
\boxed{
\Delta_U(t) = U(CG_A,t)
\ominus
U(CG_B,t)
}
$$

## What the Figure Shows

A static graph comparison can hide:

* missing paths;
* unexpected branches;
* altered reachability;
* local functional differences;
* deeper structural divergence.

A trigger exposes the hidden difference.

This gives the canonical CGU warning:

$$
\boxed{
What\ Looks\ the\ Same\ When\ Folded
May\ Differ\ When\ Unfolded
}
$$
